Visión general

Replicant Lab separa estación de trabajo, servidor Linux local, repositorios Git y servicios cloud. GitHub es la fuente de verdad del código y de la configuración versionable; datos, secretos y backups permanecen fuera de Git.

Regla crítica: no ejecutar simultáneamente tareas reales equivalentes en Nexus y DigitalOcean. Antes de activar Nexus con estado real debe sincronizarse de forma controlada el tasks.local.json vivo de producción.

Documentación y descargas

./mkdocs.yml  → /docs/mkdocs.yml
./docs        → /docs/docs

Replicant Lab usa MkDocs Material en modo serve con bind mounts. Para cambios normales en Markdown o mkdocs.yml, basta git pull; no hace falta rebuild ni reiniciar Docker.

La interfaz web usa un icono de descarga en la cabecera, junto al control claro/oscuro. Ese icono abre una página única con las opciones HTML autónomo y PDF Pro. Las descargas se fuerzan desde Nexus mediante JavaScript y fetch(), sin depender de GitHub Raw ni de cómo el navegador interprete el MIME del HTML.

Contrato Codex por aplicación

Codex debe leer primero la ficha real de cada aplicación y no asumir que dos despliegues son iguales. Debe identificar host, puertos, Compose/systemd, persistencia, secretos, proxy, datos y diferencias Nexus/producción antes de actuar.

El cierre por app exige: validar técnicamente, cerrar en Git, actualizar ficha e índice, y regenerar/publicar HTML autónomo + PDF Pro.

Invariante documental: la documentación web debe ofrecer un acceso visible a la página de descargas y ambas opciones deben descargar realmente desde Nexus. Codex debe verificar que los ficheros existen, están actualizados y no abren GitHub, no muestran código en pantalla y no devuelven 404.
